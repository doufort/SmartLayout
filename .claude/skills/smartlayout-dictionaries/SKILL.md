# Словари SmartLayout

Файлы лежат в `Resources/` и копируются `build_app.sh` в `SmartLayout.app/Contents/Resources/`. Загружает их `WordStore.reload()` (`Sources/SmartLayout/WordStore.swift`), пользователь может перечитать их из меню «Перечитать словари».

| Файл | Формат | Смысл |
|---|---|---|
| `slang_ru.txt`, `slang_en.txt` | одно слово на строку, нижний регистр | слова, которые **никогда** не исправляются |
| `typos_ru.txt`, `typos_en.txt` | `ошибка=исправление`, ключ — одно слово в нижнем регистре | автозамена частых опечаток |
| `style_profile.json` | `{"description": str, "samples": [str], "words": [str]}` | стиль автора для промптов ИИ |

Строки, начинающиеся с `#`, — комментарии. Кодировка UTF-8 без BOM, переводы строк LF, в конце файла перевод строки.

## Порядок работы

1. Прочитай нужный файл целиком, проверь, нет ли слова уже в другом словаре (`grep -rn 'слово' Resources`).
2. Правило выбора файла:
   - пользователь пишет так **намеренно** (сленг, жаргон, сокращение) → `slang_*.txt`;
   - это **ошибка**, у которой одно очевидное исправление → `typos_*.txt`;
   - слово не может быть одновременно в сленге и в опечатках (валидатор это ловит).
3. Опечатка из `typos_*` применяется **даже если слово существует** (`CorrectionEngine.evaluate`, до проверки словарём macOS). Поэтому не добавляй в `typos_*` ключи, которые сами по себе являются реальными словами (`cant`, `ill`, `wed`, `были`…): они будут ломать правильный текст. Если сомневаешься — не добавляй.
4. Исправление не должно само быть ключом (никаких цепочек `а=б`, `б=в`).
5. После правки PostToolUse-хук сам запускает `tools/check_dicts.py` и тесты. Если хук вернул ошибку — исправь её, не обходи.
6. Вручную: `python3 tools/check_dicts.py && python3 -m pytest -q pytests/test_dictionaries.py`.

## Как это работает в коде

- Ключ сравнивается без учёта регистра, регистр исправления подстраивается под набранное (`TextUtils.matchCase`): `Вообщем` → `В общем`.
- Слово из `slang_*` или из `~/Library/Application Support/SmartLayout/user_words.txt` считается правильным: его не исправляет ни движок, ни раскладка, и ИИ получает его как «слово автора».
- Новые случаи в коде проверяй тестами в `Tests/SmartLayoutTests/RegressionTests.swift` (`WordStoreTests`, `CorrectionEngineTests`): там словари берутся из `Resources/` через `TestFiles.resources`.

## Важно

- `pytests/test_bundle.py::test_repo_dictionaries_match_build` сравнивает словари в репозитории со сборкой в `dist/`. После правки словарей этот тест **ожидаемо** падает, пока не собрана и не положена в `dist/` новая версия `.dmg`. Сообщи об этом пользователю, не подгоняй тест.
- Слова из `style_profile.json["words"]` и сленг, который профиль называет намеренным, должны быть в `slang_ru.txt` (это проверяет тест).
